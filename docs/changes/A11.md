# A11: prepared demo wallets, funded seed and local-chain verification

## Summary

Add explicit demo preparation and seeding commands. Preparation creates real
random test-wallet keys only in ignored environment files and prints public
addresses. Seeding validates Arc testnet, funds three operator-controlled demo
members, creates a trip, deposits exact USDC and sets each wallet's own policy.

## Files

- scripts/prepare.ts, seed.ts, config.ts and demo.env.example
- Root demo commands and ignored local runtime outputs
- apps/api/src/integration/local-chain.ts and flow.test.ts
- docs/DEMO.md and ticket browser captures

## Interfaces touched

`bun run demo:prepare`, `bun run demo:seed`, and `bun run demo:seed --local`.
New seed settings: DEMO_MEMBER_1_PRIVATE_KEY, DEMO_MEMBER_2_PRIVATE_KEY,
DEMO_MEMBER_3_PRIVATE_KEY, DEMO_DEPOSIT_USDC and DEMO_TRIP_NAME.
Local runtime overrides are generated separately from private package env files.

## Verification

- A real local Anvil node executes factory/vault deployment, token transfers,
  deposits, policies, automatic proposals, payment, wallet-bound attestations,
  deadline refunds and withdrawals.
- TypeScript quote hashes exactly match Solidity quoteDigest.
- Durable indexer restart does not duplicate events; non-participants retain funds.
- A separate CLI/server smoke pass runs prepare and seed, starts API, merchants
  and web, signs in over HTTP, buys through the API and watcher, retrieves the
  authenticated ticket, verifies the QR page and captures 390/1280px screenshots.
- Private keys and runtime databases remain ignored; the public Arc deployment
  record is not populated with a local-node address.

## Follow-ups

Live World registration/human login and Circle faucet funding require owner
interaction. Local tests explicitly inject their World test provider and use a
mock ERC20 on a standard local EVM; they do not certify Arc native-gas behavior
or real World enrollment.
