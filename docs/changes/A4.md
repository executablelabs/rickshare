# A4: delivery escrow, refunds and pull settlement

## Summary

Pay only the quoted merchant when it issues a nonempty ticket hash before the
deadline. Expired purchases restore the exact original shares. Members can
withdraw unlocked funds at any time, including after settlement; settlement
never redistributes money or loops over potentially failing recipients.

## Interfaces touched

fulfill, refund, withdraw, settle and corresponding terminal/accounting events.
The member balance includes cumulative withdrawn amount for accounting history.

## Verification

Unit tests exercise payment timing, wrong merchants, duplicate/late delivery,
pending versus locked refunds, protected funds, pending-consent withdrawals and
post-trip settlement. Stateful tests randomize deposits, policies, proposals,
approvals, withdrawals, delivery, expiry and refunds while checking vault token
conservation, exact per-person ownership and actual merchant receipts.

## Follow-ups

A5 deploys the factory. A7/A10 consume events for indexing and ticket delivery.
Unsolicited direct token donations remain unallocated surplus; they are not
credited to members or redistributed by an administrator.
