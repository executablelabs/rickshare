# A7: durable chain projections and replayable events

## Summary

Scan factory creation and vault events in bounded block ranges. Fetch snapshots
at a fixed block, then atomically commit unique chain logs, member/proposal
projections, a durable notification outbox and the finalized cursor. In-memory
notifications publish only after commit and reconnects replay persisted IDs.

## Files

- apps/api/src/modules/indexer
- apps/api/src/runtime.ts, app.ts and index.ts
- apps/api/src/db/schema.ts and drizzle migrations
- apps/api/src/config.ts and .env.example
- docs/API.md

## Interfaces touched

IndexerService and TripEventBus; authenticated GET /trips/:tripId/events.
The runtime shares one database across sessions and projections. Add
ARC_START_BLOCK and INDEXER_POLL_INTERVAL_MS configuration.

## Verification

Tests inject RPC failures, restart the service, overlap sync calls, advance
financial state, replay event cursors, check post-commit publication and reject
unexpected finalized-history rewrites. Production RPC reads use fixed block
numbers and strict ABI event decoding. Full workspace checks run before commit.
