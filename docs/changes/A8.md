# A8: fresh World identity and approval attestations

## Summary

Add session-bound OIDC linking and per-purchase step-up flows. Verify the real
provider's JWKS-signed token, nonce, issuer, audience, authorized party, expiry
and fresh auth_time, then match the linked subject before signing the exact
current onchain share and nonce. No authentication bypass is configurable.

## Files

- apps/api/src/modules/approvals
- apps/api/src/db/schema.ts and world approval migrations
- apps/api/src/runtime.ts, app.ts and indexer/source.ts
- docs/API.md and docs/world-debrief.md

## Interfaces touched

World status/link/start/callback/request/cancel routes and per-proposal approval
start. World flows and hashed identity links persist in SQLite. Configured
World age and attestation TTL are bounded to at most 900 seconds. The indexer
includes actual World-link state in member projections.

## Verification

Real RSA JWT tests cover success and invalid claims/signatures. Service tests
cover successful contract-signature generation, wrong linked subject, browser
session isolation, replay, expiry, denial and cancellation races. HTTP callback
and polling tests verify the handoff to the web origin. Full checks run before
commit; live registration/human verification remain external setup requirements.

## Follow-ups

Owner World account access is needed to register/configure an OIDC app and test
live auth_time behavior. The separate IDKit human-in-the-loop product is
documented in world-debrief.md rather than conflated with OIDC integration.
