# A9: verified proposals and participant-only ticket retrieval

## Summary

Validate canonical signed quotes, vault/chain binding, allowlisted merchants,
members and exact shares before sending through the proposer key. Serialize
proposer transactions and persist intent before broadcast so ambiguous failures
cannot create duplicate purchases. Recover from durable indexed chain history.

## Files

- apps/api/src/modules/proposals
- apps/api/src/runtime.ts, app.ts, config.ts and .env.example
- apps/api/src/db/schema.ts and proposal submission migration
- packages/shared/src/merchants.ts and stricter SignedQuote boundaries

## Interfaces touched

ProposalService.submitProposal implements the agent handoff with tripId, signed
quote and bigint shares. Add merchant catalog/quote, proposal listing/submission
and participant-only ticket routes. Shared catalog/request/ticket-bundle schemas
keep API and merchant processes consistent. Add MERCHANTS_API_SECRET to API config.

## Verification

Real signed quote tests reject wrong context, modified quotes, invalid shares,
unlisted merchants, non-members and expiry. Replay/receipt-loss tests prove the
same quote is broadcast once; queue tests serialize proposer transactions.
Ticket tests reject non-participants, payload tampering and duplicate holders.
Merchant client tests preserve configured URL prefixes and keep secrets in headers.
