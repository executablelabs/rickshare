# B2: embedded wallet and SIWE session

## Summary

Add email-based Privy embedded wallets on Arc testnet and connect them to the existing
browser-bound SIWE API. Guard home and trip routes until the API session matches the
current account, and isolate private query caches and UI across account changes.
Missing application configuration displays a setup message.

## Files

- apps/web/src/auth/: lazy wallet provider, Arc signing adapter, session coordinator, guard and tests.
- apps/web/src/lib/auth.ts: typed Hono auth requests with validated responses.
- apps/web/src/providers.tsx: account-scoped query caches and private UI lifetimes.
- apps/web/src/routes/: guarded home/trip layouts and sign-out actions.
- apps/web/src/router.test.tsx and components/shell/AppShell.test.tsx: authenticated routing fixtures; existing navigation assertions retained.
- apps/web/package.json and bun.lock: Privy React SDK and direct viem dependency.
- apps/web/.env.example and README.md: public app ID, allowed origin and cookie-hosting setup.
- docs/changes/B2-sign-in-{390,1280}.png: actual browser captures with the app ID absent.

## Interfaces touched

Consume existing `/auth/nonce`, `/auth/verify`, `/auth/session` and `/auth/logout` routes.
No server or shared interface changes. Privy supplies the member wallet; it does not replace
SIWE authentication or World verification.

## Verification

- Web TypeScript, Vitest (64 tests), and production build: pass.
- Full `bun run check`: pass (64 web, 91 API, 18 shared, 6 merchant and 98 contract tests).
- Browser: private Plan URL renders the setup state at 390px and 1280px; captures reviewed.

- Stubbed API: wallet-bound SIWE content, rejected signatures and retry, account changes while signing,
