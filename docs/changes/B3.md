# B3: wallet-signed trip creation and single-use invitations

## Summary

Connect the backend to factory creation, trip discovery, ongoing membership and
creator-signed invitations. The backend prepares transactions and verifies chain
receipts; it never gains an ability to transact as a member or invite without
the creator's existing contract authorization.

## Files

- apps/api/src/modules/trips/{chain,schemas,service,routes,trips.test}.ts
- Shared WalletTransaction schema
- Trip/creation/invitation/member-label database tables and migration
- Runtime routing and metadata projection refresh
- Local-chain integration coverage

## Interfaces touched

Trip list/prepare/confirm/read/rename/profile routes; owner invitation management,
atomic recipient claims, exact EIP-712 authorization and wallet join confirmation.
See docs/API.md for the two-wallet invitation handshake. No new env keys or
server membership/fund authority are introduced.

## Verification

Unit tests reject non-creator management, duplicate/racing claims, invalid owner
signatures, wrong recipients, already-member claims and expired requests. Real
local contracts execute the prepared creation and join transactions, verify
creator signature parity, preserve other wallets and update profile projection
metadata without waiting for another financial transaction.
