# B6: authenticated chat, scoped agent runtime and resumable SSE

## Summary

Wire the merged agent into real trip, merchant and proposal services. Persist
chat/itinerary changes with a durable event outbox, support replayable member-only
SSE and deduplicate client message retries before any model/purchase side effect.

## Files

- Chat coordinator, schemas, routes, stream transport and integration tests
- Shared event persistence helper and optional ChatMessage.clientRequestId
- Chat request ledger and nullable message request-id migration
- Runtime model/port factories, explicit quote activity times and trusted clock context
- Local contract/chat/merchant integration coverage

## Interfaces touched

Authenticated GET/POST chat, GET itinerary and GET stream routes. POST chat uses
a client request UUID; sender identity comes from the session. Runtime ports are
trip-bound. Last-Event-ID replay uses persisted ordered IDs, with heartbeat and
session revocation checks. Ticket links are redacted from group notifications.
See docs/API.md for the full handoff.

## Verification

Tests cover duplicate/concurrent sends, sender spoofing, cross-member request-ID
reuse, interrupted-turn recovery, atomic chat/outbox rollback, replay cursors,
subscribe/replay races, out-of-order notifications, listener cleanup, logout and
ticket-URL privacy. A scripted model drives actual local contracts through
get_trip_state, a signed merchant quote, a real proposal, itinerary persistence,
watcher payment and authenticated ticket retrieval. Unit tests never call paid APIs.
